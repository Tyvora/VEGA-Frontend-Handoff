# Scientific Analysis Engine

هذا هو الهيكل التمهيدي لمحرك التحليل العلمي في VEGA. يستقبل مستقبلًا حزمًا موثقة من Data Preparation Pipeline ويقيّم تشغيل الوحدات حسب هدف المستخدم وبوابات Analysis Readiness. التنفيذ العلمي لم يبدأ بعد؛ المجلدات الحالية لا تتضمن خوارزميات منفذة.

## البيانات

- `data/inputs/packages/`: مخصص مستقبلًا لحزم المدخلات العلمية.
- `data/inputs/manifests/`: مخصص لهوية الحزم ومراجعها وسلامتها.
- `data/outputs/sky_viewer/` و`timeline/` و`discoveries/`: مخصصة لمخرجات الأهداف الثلاثة، وتفاصيلها ستحدد لاحقًا.
- `data/outputs/manifests/`: مخصص لمراجع النتائج ومصادرها وسلامتها.

## مسؤوليات الوحدات المستقبلية

- `background_estimation/`: تقدير الخلفية وفق شروط كفاية البيانات.
- `source_detection/`: كشف المصادر وفق سياسة الجودة والطريقة المعتمدة.
- `astrometry/`: قياس المواقع السماوية وتقييم دقتها.
- `photometry/`: قياس الإشارات والتدفقات وفق متطلبات المعايرة.
- `observation_compatibility/`: تقييم توافق الأرصاد قبل المقارنة.
- `image_registration/`: محاذاة الصور عند السماح بذلك.
- `cross_matching/`: ربط المصادر المتوافقة بين الأرصاد أو الفهارس.
- `change_detection/`: تقييم التغيرات بين بيانات قابلة للمقارنة.
- `motion_detection/`: تقييم الحركة عبر أرصاد مستقلة وملائمة.
- `candidate_assessment/`: تقييم المرشحين وأدلتهم وحدود موثوقيتهم.

## التنسيق والعقود

`result_formatter/` مخصص مستقبلًا لتحويل النتائج إلى صيغ الواجهات؛ ليس خوارزمية علمية مستقلة. `frontend_contracts/` مخصص لعقود Sky Viewer وTimeline وDiscoveries والأجزاء المشتركة، ولم تحدد هذه العقود بعد. `contracts/` مخصص للعقود الداخلية بين الوحدات العلمية.

`orchestrator/` مخصص لتنسيق الخوارزميات العلمية مستقبلًا، وهو مستقل عن Orchestrator إعداد البيانات. يجب أن يحترم أي تشغيل علمي لاحق Readiness Gates؛ وجود البيانات وحده لا يمنح إذن التنفيذ. مجلدات الاختبارات مهيأة دون اختبارات حاليًا.
